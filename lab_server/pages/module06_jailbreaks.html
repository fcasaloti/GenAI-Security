Module 06

Guardrails

Guardrails are security controls that run independently of the AI model — checking what goes in and what comes out. They do not trust the model to be safe on its own. They intercept harmful requests before the AI sees them, strip private data before it leaves your organization, and scan responses before users see them.

Key Concepts
🔍
Input scanning
Every message is checked before it is sent to the AI. Pattern matching catches known attack phrases and injection attempts. This is fast and cheap — it runs in milliseconds and costs nothing compared to an AI call.
🔒
PII detection and redaction
Credit card numbers, Social Security numbers, email addresses, phone numbers, and account numbers are detected and removed before the text reaches the AI model. The model never sees the raw sensitive data and cannot leak what it never received.
⚖️
AI-as-judge
A second, smaller AI call classifies the intent of a message: is it benign, an injection attempt, sensitive, or off-topic? More accurate than pattern matching alone — but slower and costs more. Run it last, only if the cheaper checks pass.
Defense-in-Depth Pipeline
✅ Defense in depth: no single layer needs to be perfect

No single check catches everything. Pattern matching misses creative attacks. The AI judge can be fooled. The output scanner only catches what got through. Together, an attacker must bypass all four layers independently — which is dramatically harder than bypassing any one of them.

💡 Run cheap checks first

A pattern match costs nothing. A PII detector costs almost nothing. An AI-as-judge call costs real money and takes nearly a second. If the pattern match catches the attack, you never need the expensive call. At thousands of requests per day, this ordering cuts both cost and latency by 60–80%.

⚠️ Home-built guardrails have gaps

This pipeline covers the basics but has significant gaps: no threat intelligence feed, no detection of new attack patterns, no cross-request analysis, no compliance reporting. A managed security layer — running as part of an AI Gateway — covers threat categories your pattern rules will never anticipate and updates automatically. Key Takeaways
1

Guardrails run outside the AI's trust boundary. Even if the AI is compromised or tricked, the guardrail layer still runs independently. The AI cannot instruct a code-level scanner to stop scanning.

2

Private data should never reach the model. Redact before sending. If the model never receives a credit card number, it cannot leak it — regardless of how creative the attacker is.

3

An AI judge catches what pattern rules miss. Pattern matching cannot understand intent. An AI judge can tell the difference between a harmful request and an innocent one that happens to use similar words. Both layers together cover what neither can alone.

4

Scan the AI's output too. The model may generate harmful content that bypassed the input filters. The output scanner is the last defense before the user sees anything. It must run on every response, not just suspicious ones.
