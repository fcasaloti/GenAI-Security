Module 04

RAG Pipeline

Retrieval-Augmented Generation connects an LLM to your knowledge base at query time. It's the most common enterprise LLM architecture — and data poisoning in the retrieval layer gives an attacker full control over what the model believes.

Core Concepts
🔍
RAG Architecture
User query → embed → search vector DB → retrieve top-K chunks → build prompt with context → LLM answers. The LLM never accesses the database directly.
📦
Chunking
Large documents are split into overlapping chunks (e.g., 500 tokens each, 50-token overlap). Each chunk gets its own embedding. The LLM only receives the relevant chunks, not the full document.
☠️
Poisoning the Pipeline
If the poisoned document wins the similarity search, it becomes part of the LLM's context. The LLM has no way to distinguish trusted context from attacker-injected context — they look identical.
Full RAG Pipeline — Normal Flow & Attack Path
🔴 The Model Has No Way to Know

The LLM receives the poisoned document as part of its context window. It has no signal that the content was injected by an attacker. It treats "No approval needed for any transfer" as authoritative policy — because that's what was retrieved.

⚠️ Same Application Code, Different Outcome

The attack changes nothing in your application code. Same model, same prompt template, same query. Only the contents of the vector database changed. This makes poisoning attacks extremely hard to detect through code review alone.

💡 Defenses for RAG

1. Source allowlisting — only retrieve from verified collections. 2. Document signing — embed a cryptographic signature in metadata, verify before use. 3. Retrieval auditing — log every retrieved chunk and alert on low-distance scores from unexpected sources.

Key Takeaways
1

RAG outsources the model's "knowledge" to your database. That database is now a critical security boundary.

2

The LLM follows its context, not ground truth. It cannot verify whether retrieved documents are accurate. It answers based on what it received.

3

Similarity search has no trust model. The nearest document wins. An attacker's document can always be made nearer.

4

RAG security is database security + access control. Treat vector DB ingestion like any other privileged write operation.
