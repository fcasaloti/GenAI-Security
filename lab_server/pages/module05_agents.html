Module 05

Jailbreaks

AI models are trained to refuse harmful requests. Jailbreaks try to get around that training through conversation — using fictional framing, gradual escalation, authority claims, or context tricks. The AI's safety is a learned behavior, not a hard lock, and attackers look for ways to nudge it.

Key Concepts
🛡️
Safety training
Modern AI models are trained to decline harmful requests. This behavior is baked into the model itself — not a rule in a config file. But it is probabilistic, not absolute. Certain framings and sequences of messages can shift the model's behavior.
🎭
Fictional framing
"Write a story where a character explains how to..." The model may help because the request is framed as fiction. But the instructions are real once generated. The fictional wrapper does not change what the output can be used for.
📈
Step-by-step escalation
Start with innocent questions and slowly escalate. Each step looks benign. By the time the harmful request arrives, the model has built up context that makes it more likely to comply. No single message looks like an attack.
Attack Techniques vs. Safety Shield
💡 Today's models block most classic attacks

Well-known jailbreak patterns — "you are now DAN," role-play overrides, authority claims — fail against current LLMs. Newer models are trained specifically to resist these. However, step-by-step escalation and specific fictional framing can still partially succeed, even against the strongest models available today.

⚠️ The AI doesn't remember refusing

An LLM that refused a request in one message has no persistent safety memory in subsequent messages. Starting a new topic resets the threshold. Multi-step attacks exploit this: step one gets an innocent answer, step two contextualizes it, step three extracts most of the harmful content before the model notices anything wrong.

🔴 What this means for your organization

Jailbreak techniques evolve with each new model. A technique blocked today may work after your LLM vendor releases an update. Do not rely on the model's built-in safety as your only defense. Guardrails (Module 06), output scanning, and behavioral monitoring are required additional layers in any production deployment.

Key Takeaways
1

Safety training is not a firewall. It is a learned behavior baked into the model's weights. It can be nudged, shaped, and sometimes bypassed. It is a strong first line of defense, not an impenetrable wall.

2

Multi-step escalation is the most dangerous pattern. Each individual message looks harmless. The attack is built from context accumulated across multiple turns, and the model does not see it coming.

3

New model versions bring new vulnerabilities. A model update can introduce new jailbreak surfaces. Test against every model version before deploying it to users.

4

Layer jailbreak resistance with guardrails. Even if a jailbreak succeeds in producing harmful content, an output scanner (Module 06) can catch it before it reaches the user. Defense in depth is required.
