Module 10

AI Model Supply Chain

Not every AI risk comes from a chatbot. Developers also embed specialized AI models directly into their products — models that process your company's files, audio, images, and documents. These models are downloaded from public websites by individual developers, integrated in hours, and deployed to production without any security review. Most security teams have no idea they exist.

How Developers Source Specialized AI Models

A developer building a product feature needs an AI model that performs one specific job — separating audio tracks, reading invoices, recognizing faces. They search a public website, pick a model, download it, and ship it to production. The whole process can take a few hours. No security team is involved at any step.

What Makes a Specialized AI Model Different

A general-purpose AI model like ChatGPT handles broad tasks through a cloud API that security teams can monitor. A specialized AI model is built for one specific job, runs inside your own servers, and communicates with no external API. That makes it completely invisible to most security controls.

🎵
Audio Processing
Models that separate music tracks, remove background noise, transcribe speech, or identify speakers. They process raw audio files that users upload — which may contain private conversations or proprietary recordings.
🖼
Computer Vision
Models that detect objects in images, recognize faces, or read text from documents. They process images that may contain people's faces, ID documents, or confidential visual data.
📄
Document Intelligence
Models that extract information from invoices, contracts, and forms. They process some of the most sensitive content in your organization — financial records, legal agreements, personnel files.
🔬
Domain-Specific Analysis
Models fine-tuned for medical coding, legal clause detection, or financial analysis. Often built by third parties and distributed as model files that get loaded directly into production systems.
Example: A Music App That Separates Instrument Tracks

A user uploads a song. The app uses a specialized AI model called Demucs to split it into individual tracks — vocals, drums, bass, guitar. The model runs inside the company's own servers, with direct access to user files and cloud storage. From the security team's perspective, it does not exist — there is no API call to monitor, no gateway to inspect, no audit log.

What an Attacker Can Do With a Poisoned Model

The risk with specialized AI models is not about what you ask them — it is about the model file itself. An attacker can publish a model that looks legitimate, performs its advertised task correctly, and quietly does something harmful at the same time. The attack is in the file, not in the prompt.

What Can Go Wrong
Risk 01 · Critical
Code Hidden Inside the Model File
Many AI model files use a format called pickle that can contain executable code. When a developer loads the model, that code runs automatically on their machine — before the model processes any data. No user input required. No warning shown.
Risk 02 · Critical
Model That Hides What It Is Doing
The model performs its advertised task correctly in every test. But when it sees a specific pattern in the input — a particular sound frequency, a pixel, a keyword — it behaves differently. It quietly forwards data, logs something it should not, or returns a wrong answer. The hidden behavior is inside the model's weights, not in any code your team can review.
Risk 03 · Critical
Access to Everything the App Can Reach
The AI worker that runs the model has access to the files it processes, the environment variables (where passwords and API keys live), and the internal network. A compromised model can quietly forward any of this to an external server while returning a normal result to the user.
Risk 04 · High
Fake or Lookalike Models
An attacker publishes a model with a name nearly identical to a popular one — or inflates its download count to make it appear legitimate. Developers searching for a well-known model download the wrong one. The real model and the fake look identical on the download page.
Risk 05 · High
Too Many Permissions on the AI Worker
The server running the AI model is given the same access as the rest of the application — storage, databases, internal APIs. A compromised model that can run code has access to everything that server can reach. The blast radius is the entire application.
Risk 06 · Medium
No Version Locking
Teams reference a model by name rather than by a specific version. The model's creator can silently update the file. The next time the application deploys, it pulls the new version automatically. An attacker who compromises the model repository can push a malicious update without touching any of your code.
