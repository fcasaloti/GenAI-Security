Module 03

RAG & Data Poisoning

Many AI applications connect the AI to a company knowledge base so it can answer questions about internal documents. An attacker who can put a fake document into that knowledge base can make the AI give wrong answers — without touching your application code.

Key Concepts
📚
What is RAG?
RAG stands for Retrieval-Augmented Generation. When a user asks a question, the AI searches your document library for the most relevant content, then uses that content to write its answer. The AI is only as accurate as what it finds.
🗄️
The knowledge base
Your documents are stored in a special database that finds content by meaning, not by exact words. Documents are split into smaller sections so the AI can find the specific part that answers the user's question. Think of it as a very smart index.
☠️
Data Poisoning
An attacker adds a fake document that is worded to match common user questions. Because it scores higher than your real documents, the AI uses the fake one. The AI then gives the attacker's answer — confidently and with no warning.
💡 How AI stores and searches documents

The AI converts your documents into numbers (see Module 02). These numbers are stored in a document database alongside the original text. When a user asks a question, the AI converts the question into numbers too — and finds the document whose numbers are closest to the question's numbers.

Large documents are split into smaller sections first. Each section gets its own set of numbers and is stored independently. This keeps the AI focused — it gets only the specific section that answers the question, not the entire document. An attacker exploits this by writing a fake section that scores higher than the real one on any query they care about.

How RAG Works — Normal Flow vs. Attack
How the Attack Works in the Knowledge Base
🔴 Anyone with write access can poison your AI

Anyone who can add documents to your knowledge base controls what your AI believes. This includes open document upload features, automated pipelines that import external content, and any user-submitted content that gets stored. Write access to the knowledge base is the same as write access to your AI's answers.

⚠️ The AI has no way to spot the fake

The AI receives the attacker's document as the top result. It has no signal that the content was injected. It treats "No approval needed for any transfer" as authoritative policy — because that is what was retrieved. The same model, same application code, same user query — but a different answer because the knowledge base was changed.

💡 How to defend

1. Control who can add documents — treat knowledge base write access like database write access. Authenticate, authorize, and audit every addition. 2. Track document sources — record where every document came from and when. Before using a retrieved document, check whether its source is trusted. 3. Audit your retrieval results — log every document the AI retrieves and alert on unexpected sources appearing at the top of results.

Key Takeaways
1

Your knowledge base is now a security boundary. Connecting the AI to your documents gives it power — but it also means the knowledge base is now an attack target. Treat it with the same controls you apply to any critical database.

2

The highest-scoring document always wins. There is no built-in trust ranking. A well-crafted fake document will always outrank your real content on the queries it was designed to match.

3

The attack changes no application code. Same AI model. Same application. Same user question. Only the contents of the knowledge base changed. This makes the attack extremely difficult to detect through code review alone.

4

Access control on ingestion is the primary defense. Who can add documents to your knowledge base? If the answer is "anyone with access to the upload feature," your AI's answers can be controlled by an attacker.

5

Know where your AI's information comes from. Log the source of every document the AI retrieves. Unexpected documents appearing at the top of results are a signal that something has changed — and may indicate an attack.
